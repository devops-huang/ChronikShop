# 里程碑、工作量与报价（讨论稿）

> 前提：客户会签 NDA 后给"系统清单 / 订单量 / 样本单 / CSV 规范"。**报价基于典型情形假设**，签字前用真实样本量校准一次。
> 假设：订单量 100–300 单/日、客户数 50–300、料号 3k–20k 行、PDF 以系统导出为主 + 约 20–30% 传真/扫描、CSV 规范 1 张表 15–25 列。

## 1. 报价（推荐口径）

| 里程碑 | 内容 | 周期 | 固定价（USD） | 弹性区间 |
|---|---|---|---|---|
| **M1 — 可运行原型** | 客户样本单跑通端到端，输出正确 CSV + 复核页 + 指标 | 2 周 | **$7,500** | $6,000 – 9,500 |
| **M2 — 生产就绪** | 客户 Azure 环境部署、PA/Graph 触发、主数据接入、复核工作流、联调、文档与交接 | 4–6 周 | **$22,000** | $18,000 – 28,000 |
| **合计（建议首报）** | | 6–8 周 | **$29,500** | — |
| **可选：持续支持** | 见 §4 | — | **$1,900/月**（含 8h）或 **$135/h** | $1,600–2,400/月 |

**为什么是这个量级（给客户的解释，也是我们自己的成本核算）**
1. 真实难度在**主数据匹配 + 校验规则库**，不在模型调用。料号 crosswalk、收货地址消歧、UOM 冲突、金额对账这四件事占了 M2 一半工作量，也决定了能不能"不误配"。
2. 文档质量分级（扫描/旋转/手写/未见格式）需要**样本集 + 回归测试**，这是客户要"可交接"的必要条件，不是可选项。
3. 交付物包含运维文档 + runbook + 回归样本集；客户明确要求"另一个开发者能维护"，这部分不能省。
4. 我们自己要预留 20% 缓冲：真实传真比任何合成样本都脏，M1 出结果后 M2 的规则一定会长。

**报价策略建议（Upwork 场景）**
- 首报用 **M1 $7,500 / M2 $22,000**，并在提案里强调"**M1 结束不满意可终止，仅付 M1**"——这是把风险还给我们的姿态，也是这类客户最认的一句话。
- 若客户明确压价：M1 压到 $4,800（缩到 1 周、只做 3 类文档、不做复核页图形化），但 **M2 不压**——压 M2 等于压准确率，最后返工更贵。
- 不要接"按单计价"或"按准确率对赌"：订单量不可控，准确率口径可被任意解释。

## 2. M1（2 周 / 10 个工作日）：可运行原型

**验收（写进合同）**：给我们 ≥20 份真实样本单（覆盖 ≥5 个客户格式，含至少 2 份传真/扫描、1 份手写），系统对每份产出 1 个 CSV，字段准确率 ≥ 95%，且所有不确定字段都有可定位的 flag。

| 天 | 工作 | 产出 |
|---|---|---|
| 1 | NDA 后技术对接：CSV 规范确认、主数据导出格式、共享邮箱/Graph 权限清单 | 接口清单 + 权限申请单 |
| 2–3 | 接入客户样本：页面 triage、渲染、旋转矫正；建立样本集与评分脚本 | 样本基线报告（哪些格式会掉点） |
| 4–5 | 抽取 prompt v1 + 严格 JSON Schema；文本层/扫描件双路径 | 抽取结果 JSON |
| 6–7 | 主数据匹配（客户/收货地址/料号 crosswalk/UOM/价格）+ 校验规则 | flag 规则库 v1 |
| 8 | CSV 生成（按客户规范）+ 幂等文件命名 | 首批 CSV 交集成商 |
| 9 | 复核页（HTML，含原文截图）+ Teams 通知 | 复核台 v1 |
| 10 | 指标看板 + 演示 + 差距清单 + M2 详细计划 | 演示视频 + M1 报告 |

**M1 风险与应对**：若客户样本里手写比例 > 15%，M1 的"字段准确率 ≥95%"要拆成"系统导出类 ≥97% / 扫描类 ≥92% / 手写类按行计算并标注"。

## 3. M2（4–6 周）：生产就绪

| 阶段 | 内容 | 周 |
|---|---|---|
| A 基础设施 | Azure 资源（Container App / Storage / Queue / Key Vault / App Insights）以客户名义部署，Bicep 或 azd 一键；Managed Identity；私有端点（如需） | 1 |
| B 邮件接入 | Power Automate 薄触发 + Graph 附件下载 + 去重（按 message-id + 附件哈希）+ 死信与重试 | 1 |
| C 主数据同步 | ERP 客户/地址/料号/价格 CSV 夜间同步；变更检测；匹配阈值可配置 | 1–2 |
| D 准确率工程 | 客户样本回归集（≥100 单）、按 flag 类型调参、阈值分级、hold-out 格式测试 | 2–3（与 C 并行） |
| E 复核工作流 | Teams 卡片 + 复核页 + 一键"确认/修正/重出 CSV"（attempt 递增，旧文件归档）+ 抽样审计报表 | 3–4 |
| F 联调与 UAT | 与 ERP 集成商联调 100% 样本；与 2–3 名客服代表做 UAT；修 bug | 4–5 |
| G 交接 | 运维手册、runbook（换模型/改字段/加 flag 怎么做）、权限与成本说明、知识转移会议 | 5–6 |

**M2 验收**：
- 回归集上自动放行率 ≥ 60%（干净 PDF 场景 ≥ 85%），**误配率 = 0**（宁可 flag）
- 客服代表平均复核耗时 ≤ 90 秒/单（对比基线：手工录入通常 3–6 分钟）
- 端到端 P95 ≤ 90 秒/单；单日 500 单压测通过
- 全部代码/文档/资源在客户名下，密钥在 Key Vault，无我方账户依赖
- 单元 + 集成测试全绿（`make test`），CI 可跑

## 5. 付款与合同要点

- 建议结构：M1 50% 预付 / 50% 验收后；M2 按月 3 期（30/30/40）。
- **知识产权**：交付即归客户（含合成样本生成器、回归测试集、文档）。不接受"代码托管在我方账户"。
- **AI 使用费由客户直付** Azure 订阅——我们不转售 token（这也是他们"不要第三方按单收费"的答案）。
- 明确 out of scope：ERP 侧导入逻辑、重复单判定、票据/发票处理、非英文文档、采购以外的单据类型；如需要另立 M3。
- **数据保护**：HIPAA 相关问题需提前澄清（见风险清单 R1）。
