# 02 · 里程碑、工作量与报价 · Milestones, Effort & Pricing

> 双语：先中文，后英文。**报价是讨论稿**，签字前用真实样本量校准一次。
> *Bilingual: Chinese first, English after. Prices are a working draft — recalibrate once the client's real volumes and samples are known.*

**报价假设 · Assumptions**：订单量 100–300 单/日、客户 50–300 家、料号 3k–20k 行、PDF 以系统导出为主 + 20–30% 传真/扫描、CSV 规范 1 张表 15–25 列。
*100–300 orders/day · 50–300 customers · 3k–20k item rows · mostly born-digital PDFs with 20–30% fax/scan · CSV spec of one table with 15–25 columns.*

**为什么是这个量级 · Why this number**

1. 真实难度在**主数据匹配 + 校验规则库**，不在模型调用。料号 crosswalk、地址消歧、UOM 冲突、金额对账占 M2 一半工作量，也决定"能不能不误配"。
   *The difficulty is master-data matching and the validation rule set, not the model call — crosswalk, address disambiguation, UOM conflicts and arithmetic are half of M2 and decide whether we ship a mismatch.*
2. 文档质量分级（扫描/旋转/手写/未见格式）需要**样本集 + 回归测试**，这是客户要"可交接"的必要条件，不是可选项。
   *Document-quality tiers need a sample set and a regression harness; that is what makes the asset maintainable.*
3. 交付包含运维文档、runbook、回归样本集；客户明确要求"另一个开发者能维护"。
   *Docs, runbook and the regression set are deliverables, because the client said another developer must be able to maintain it.*
4. 预留 20% 缓冲：真实传真比任何合成样本都脏，M1 之后规则一定会长。
   *20% buffer: real faxes are dirtier than any synthetic sample.*

**报价策略 · Bidding tactic**
- 首报 **M1 $7,500 / M2 $22,000**，并强调"**M1 结束不满意可终止，只付 M1**"——把风险还给我们的姿态，这类客户最认这句。
  *Lead with M1 $7.5k / M2 $22k and offer "if the two-week prototype misses the acceptance criteria, you stop and pay only that milestone".*
- 客户压价：M1 可压到 $4,800（缩到 1 周、3 类文档、不做图形化复核页），但 **M2 不压**——压 M2 等于压准确率，返工更贵。
- 不接"按单计价"或"按准确率对赌"：订单量不可控，准确率口径可被任意解释。
  *Never accept per-order pricing or accuracy-based bonuses: volume is outside our control and the metric is open to interpretation.*

## 2. M1（2 周 / 10 个工作日）· M1, two weeks

**验收（建议写进合同）**：≥20 份真实样本单（≥5 个客户格式，含 ≥2 份传真/扫描、1 份手写），每份产出 1 个 CSV，字段准确率 ≥95%，且所有不确定字段都有可定位 flag。
*Acceptance: ≥20 real samples across ≥5 customer formats (including ≥2 fax/scan and 1 handwritten), one CSV each, ≥95% field accuracy, every uncertain field flagged with a locatable source.*

| 天 · Day | 工作 · Work | 产出 · Output |
|---|---|---|
| 1 | NDA 后技术对接：CSV 规范、主数据导出格式、邮件权限清单<br>Kickoff: CSV spec, master-data export format, mail permissions | 接口清单 + 权限申请单 |
| 2–3 | 接入客户样本：triage、渲染、旋转矫正；建样本集与评分脚本<br>Ingest samples: triage, rendering, rotation; build the scoring set | 样本基线报告（哪些格式会掉点） |
| 4–5 | 抽取 prompt v1 + 严格 JSON Schema；文本层/扫描双路径 | 抽取结果 JSON |
| 6–7 | 主数据匹配（客户/地址/料号/UOM/价格）+ 校验规则 | flag 规则库 v1 |
| 8 | CSV 生成（按客户规范）+ 幂等文件命名 | 首批 CSV 交集成商 |
| 9 | 复核页 + PNG 卡片 + Teams 通知 | 复核台 v1 |
| 10 | 指标看板 + 演示 + 差距清单 + M2 详细计划 | 演示视频 + M1 报告 |

**风险 · Risk**：若手写比例 >15%，"≥95%"需拆成"系统导出 ≥97% / 扫描 ≥92% / 手写按行计算并标注"。
*If handwriting exceeds ~15% of volume, split the target by document class.*

## 3. M2（4–6 周）· M2, four to six weeks

| 阶段 · Phase | 内容 · Work | 周 · Week |
|---|---|---|
| A 基础设施<br>Infrastructure | Azure 资源（Container App / Storage / Queue / Key Vault / App Insights）以客户名义部署，Bicep 一键；Managed Identity | 1 |
| B 邮件接入<br>Mail ingestion | PA 薄触发 + Graph 附件下载 + 去重（message-id + 附件哈希）+ 死信重试 | 1 |
| C 主数据同步<br>Reference sync | ERP 客户/地址/料号/价格 CSV 夜间同步；变更检测；阈值可配置 | 1–2 |
| D 准确率工程<br>Accuracy engineering | 客户样本回归集（≥100 单）、按 flag 类型调参、hold-out 格式测试 | 2–3（与 C 并行） |
| E 复核工作流<br>Review workflow | Teams 卡片 + 复核页 + 一键确认/修正/重出 CSV（attempt 递增）+ 抽样审计报表 | 3–4 |
| F 联调与 UAT<br>Integration & UAT | 与集成商联调 100% 样本；2–3 名客服代表 UAT；修 bug | 4–5 |
| G 交接<br>Handover | 运维手册、runbook、权限与成本说明、知识转移会议 | 5–6 |

**M2 验收 · Acceptance**
- 自动放行率 ≥ 60%（干净 PDF 场景 ≥ 85%），**误配率 = 0**
- 客服平均复核 ≤ 90 秒/单（基线：手工录入通常 3–6 分钟）
- 端到端 P95 ≤ 90 秒/单；500 单/日压测通过
- 代码/文档/资源全在客户名下，密钥在 Key Vault，无我方账户依赖
- `make test` 全绿，CI 可跑

> Straight-through ≥ 60% overall (≥ 85% on clean PDFs), **zero mismatches**, review ≤ 90 s per order, P95 ≤ 90 s end-to-end, 500 orders/day load test, everything in the client's name, tests green in CI.

## 5. 付款与合同要点 · Payment & contract

- 结构：M1 五五开（启动/验收）；M2 三期 30/30/40
- **知识产权**：交付即归客户（含合成样本生成器、回归测试集、文档）。不接受代码托管在我方账户
- AI 使用费由客户直付 Azure 订阅——我们不转售 token
- Out of scope：ERP 导入逻辑、重复单判定、审批流、发票/装箱单/ASN、非英文文档
- **数据保护**：HIPAA/BAA 需 M1 前澄清（见 `03_风险与问题清单.md` R1）

> IP transfers on delivery; the client pays Azure directly for model usage; ERP import, duplicate detection, approvals, invoices/packing lists and non-English documents are out of scope; HIPAA/BAA clarified before M1.
